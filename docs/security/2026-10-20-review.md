# Security review 2026-10-20 — remediation status

Source: external review of `origin/main @ 56aa47d` (17 findings: 1 critical, 5 high, 9 medium,
2 low). Each claim was re-verified against the code before it was changed. Branch:
`security/review-2026-10-20` (local, not pushed, not deployed).

**All 17 findings are addressed, plus one new one (#18) found during the work.** Every fix has a
test. `bun run test` (1587 tests), `bun run typecheck` and `bun run lint` are clean; `vite build`
succeeds.

## Before deploying — required, in this order

1. **Set the session secret** (without it, nobody can log in in production — fail closed):
    ```bash
    openssl rand -base64 48 | bunx wrangler pages secret put SESSION_SECRET --project-name spacebot
    ```
    It must be at least 32 characters. Rotating it logs everyone out. `spacebot` is the Pages
    project name from `wrangler.toml`; confirm it matches the dashboard. Only the Pages app reads
    it — the gateway VM does not need it.
2. **Apply migration 0079 before the new code serves traffic** (the workflow advance and cron
   dispatch read the new column/table and would error without it):
    ```bash
    bun run db:migrate:local   # verify locally first
    bun run db:migrate         # production D1
    ```
3. Deploy Pages, then the orchestrator worker as usual.
4. Restart PM2 processes that run changed code: `bun run gateway:restart` (automation engine,
   regex, channel binding, egress) and the deploy webhook process (#11).
5. Expect every user to be logged out once: pre-existing unsigned cookie sets are cleared by
   design (#1).
6. Local runners: users must update the runner CLI for the new negotiation callback (#16). Old
   runners still connect with existing tokens; only `/token` negotiation needs the new CLI.

## What changed

**#1 — session.** `src/lib/server/auth-session.ts`. The OAuth callback mints `sb_session`, an
HMAC-SHA256-signed `{uid, iat, exp}` keyed by `SESSION_SECRET`, after Discord's token exchange.
`establishSession` runs first in `hooks.server.ts` on every request: it verifies the token and
forces `discord_user_id` to the verified uid, or clears every auth cookie if there is no valid
session. This gives the ~100 existing `cookies.get('discord_user_id')` readers one invariant
instead of 100 edits. Sliding sessions re-sign the token. Dev-login issues a session too (dev
uses a fixed fallback key; production without the secret fails closed). Profile cookies remain
for display. Alternative considered: opaque token hashed in D1 (adds a D1 read per request and a
migration; would give server-side revocation — see residual risk).

**#18 — new.** `getUserGuilds` / `getBotGuildIds` fell back to `cached_user_guilds` /
`cached_bot_guild_ids` cookies and trusted them, so any signed-in user could write one claiming
ADMINISTRATOR on any guild and pass `verifyGuildAdmin` on every guild API. The cookie cache is
gone; guild lists live only in server memory (cost: more Discord API calls per isolate).

**#5 — actions.** `src/lib/server/action-guard.ts`, called from `hooks.server.ts` for every
non-GET `/admin/**` request: `/admin/superadmin/**` needs superadmin, `/admin/<guild>/**` needs
Discord ADMINISTRATOR or MANAGE_GUILD on that guild (same as the loaders). Actions that read
`guild_id` from the form now use `params.serverId`; `updateCommand` takes the owning guild and
refuses rows from another guild.

**#4 — billing.** Full Administrator (or superadmin) required before the plan row is read;
`returnUrl` must be same-origin (`src/lib/server/billing-return-url.ts`).

**#6 — artifacts.** `src/lib/server/artifact-headers.ts`: only signature-verified PNG/JPEG/GIF/WebP
render inline; everything else is `application/octet-stream` + `attachment`, `nosniff`, sandbox
CSP. External artifact redirects must be https.

**#2 — channels.** `src/lib/automation/channel-scope.ts`. All automation channel fetches
(send/log/thread/delete/buttons) and message-delete go through `fetchGuildChannel`, which rejects
a channel whose `guild_id` is not the event's guild. Deferred scheduled messages re-check the
channel's guild at delivery.

**#3 — AI tools.** `src/lib/ai/tool-authz.ts`, enforced in `executeToolCalls` for every call:
`list_guilds` superadmin-only; every other non-account tool needs a `guildId` in the
server-built managed set, and any `channelId` must belong to that guild. The runner assistant
ignores body `managedGuilds`/`isSuperAdmin`; superadmin always comes from `ADMIN_USER_IDS`.

**#7** fail closed for every non-ping event without a secret. **#17** `safeReturnPath` at OAuth
start, callback and dev-login. **#15** `src/lib/preview-html.ts`: attribute-context escaping and
http(s)-only links; channel/role names escaped. **#14** `validateManifest` rejects non-https
link fields; the admin page renders links only via `isSafeLinkUrl` (covers stored data).
**#11** `scripts/bounded-body.ts`: 2 MiB cap, Content-Length pre-check, stream destroyed on
overflow, server timeouts. **#10** `content_regex` runs on `re2js@2.8.6` (pinned, MIT, no deps)
with pattern/input caps. **#12** `src/lib/server/safe-fetch.ts` for webhooks, integration
action/command handlers, manifest fetch and health probe: public http(s) hosts only, redirects
re-validated per hop, time and byte caps; webhook URLs checked on save. **#8**
`src/lib/server/runner-limits.ts` in both WS implementations and the upload route: nothing is
written unless the job is running and held by this token/instance; caps on event details,
artifact count, per-item/per-result bytes and metadata; per-job quota on upload. **#16**
one-time 32-byte nonce in the callback path, single use, Origin must be the SpaceBot origin,
body cap; wildcard CORS removed. **#13** writes need `SPACEBOT_MCP_WRITE=true`; direct create
tools never exposed; confirm consumes a single-use 10-minute `previewId` bound to a digest of
the exact payload. **#9** run lease (`lease_until`) around each advance; cron dispatch claims
`(template_id, scheduled_minute)` by primary key; scheduled messages move pending → sending
atomically.

## Residual risk / not done

- **#1** HMAC sessions cannot be revoked one at a time before expiry (default 7 days, sliding);
  rotating `SESSION_SECRET` revokes all. The Discord access/refresh token cookies are still not
  bound to the session uid; they only ever grant what the holder's own Discord account grants.
  Logout is still a GET (logout CSRF, low impact).
- **#2** Storage-time validation of channel IDs was not added; enforcement is at execution
  (the authoritative point). Other channel sinks outside the automation engine
  (anniversary timeline, purge workflow, interactions) were not individually re-audited.
- **#3** Tool authz relies on `managedGuilds` from the gateway (live member permissions) or the
  gateway-written job snapshot; a guild a user lost admin on stays in an old snapshot until the
  next DM refreshes it.
- **#8** Large artifacts still live in D1 (no R2 offload); no per-user rate limit on WS frames.
  The claim check before artifact insert is a read, not a lock (a result racing a requeue can
  still attach artifacts; the result write itself remains conditional).
- **#9** Workflow operations are not given idempotency keys toward external services; the lease
  prevents concurrent advance, not a crash-after-side-effect replay. A crash mid-send leaves a
  scheduled message in `sending` (at-most-once, by choice) — the admin UI has no label for it.
- **#10** Patterns using backreferences/lookaround (unsupported by RE2) now never match; any
  existing automation relying on them silently stops matching.
- **#12** DNS rebinding (public name resolving to a private IP) is not caught — Workers has no
  pre-connect DNS hook. Set `OUTBOUND_ALLOW_PRIVATE=true` only in local dev.
- **#6** Artifacts are still served from the main origin (no cookieless artifact domain).
- **#13** The preview store is in memory: restarting the MCP server invalidates open previews.
- Which runner WS implementation serves production (`_functions/` vs SvelteKit route) is still
  unconfirmed; both were fixed.
- The review covered 205 of 834 paths; the deferred Svelte/UI/test/docs units were not
  re-reviewed here.
